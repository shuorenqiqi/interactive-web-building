# 经验与反思全清单（实战沉淀）

> 来源：一个完整项目（手势交互粒子网页「霜华 Frost Bloom」，单文件 HTML + MediaPipe 手势 + Canvas 粒子 + 云部署）
> 从初版到多次迭代上线的全部教训。**每条都是真踩过的**。

## 一、性能：先测量，后优化

- **血的教训：凭直觉定位瓶颈会白干。** 曾笃定"点云环形缓冲 12000 槽、每帧扫满两遍"是元凶，
  写微基准一量：**0.026ms/帧**——V8 对"取值 + 判活 + continue"优化极好，扫一万个空槽等于没扫。
  👉 处方：优化前写**只跑循环本身**的 Node 微基准（同样的数据结构 + 每帧逻辑），拿数字再动手。
- **真正的瓶颈是填充率（fill-rate）**：数每帧的**全屏操作次数**（拖尾清屏、点云拉伸、全屏闪光）。
  每次 = 宽×高×DPR² 像素。处置顺序：① 静态背景搬出 canvas（CSS 层）；② 全屏操作用纯色 `fillRect`
  代替贴图 `drawImage`（省采样）；③ 降 DPR 上限（1.5→1.25 省约 30% 像素，柔边粒子肉眼无差）。
- **分平台档位表**：桌面流畅 ≠ 手机流畅。新特性让粒子数翻倍（960→1728）后，**移动端档位表里
  "细节系数"还是满配 1**——手机一直在画满配。👉 处方：**任何让单帧负荷显著变化的改动，
  完成后必须回头核对移动端档位表**；桌面好、手机卡 = 这个症状的典型信号。
- **状态栈操作在爆发期很贵**：几百个特效件 × `save/translate/rotate/restore` → 换三角函数直算端点。
  注意 `lineCap` 等 canvas 状态不再被 save/restore 隔离，需每帧复位。
- **图像数据伪随机种子挂对象**：紧凑数组（换尾移除）替代定长环缓冲后，
  任何"用数组下标做伪随机"的写法（如 `(i*2654435761)%8`）都会因下标变动而乱闪——
  种子必须存在粒子对象上（`p.sd`），随生命周期走。

## 二、视觉：无法看图时怎么工作

- **AI 可能看不了图——不要假装能判断视觉效果。** 本项目全程靠三条替代路径：
  ① **几何快照**：driver 导出粒子坐标 JSON → PIL 加色渲染成 PNG（给人看，`scripts/snapshot_render.py`）；
  ② **数值分析**：如"粒子最近邻距离 vs 渲染尺寸"的离散度统计（点阵感是否成立）；
  ③ **用户目测终审**：给用户具体的选择题（"更圆还是更尖？卷曲要不要更强？"），而不是笼统的"好看吗"。
- **"光污染/刺眼"的标准处方**（详见姐妹技能 `canvas-particle-fx` 的配色章节）：
  纯白是总源头——辉光贴图中心、调色板、所有硬编码 strokeStyle 全链路去白；
  粒子做小比减数量有效；亮度增益乘数也要压。
- **"更像花一点" = 几何模型重写，不是调参。** 分形骨架（雪花）→ 花瓣剖面函数（倒卵形）+ 分层花瓣 +
  花蕊/花心/脉流。语义需求要翻译成几何改动清单，逐项实现。

## 三、交互系统设计

- **交互维度清单法**：列全"连续量 / 脉冲 / 状态 / 双手"四类维度再设计——
  连续量（张开度→绽放、距离→大小、手腕→朝向）；脉冲（捏合→凝霜、前推→冲击环）；
  状态（无输入时待机呼吸）；双手（间距→大小、合拢→共鸣）。空着的维度就是"交互感还能加"的地方。
- **归一化的两种用法**（同一数据两个语义，价值极高）：掌宽（归一化）= "手有多大" → 判手势类型；
  掌宽（未归一化）= "手离镜头多远" → 当测距仪。用手部自身尺寸归一化可消除距离对手势判定的干扰。
- **三端对齐**：摄像头有手势，鼠标/触摸必须有一一对应物（右键→凝霜、滚轮→大小、双指→缩放），
  且**提示文案分路**：`matchMedia("(hover: none)")` 判定触摸设备，别让手机上出现"左键/右键"。
- **失去控制时必须同步目标值**：手腕旋转→花朝向的映射里，手离开画面后主装置进入自转；
  若"目标角度"变量不跟着同步，手一回来装置会**瞬间跳回旧角度**。处方：失去控制时 `target = current`。
- **稀疏 vs 连续映射**：位置用欠阻尼弹簧（有重量感）；连续量线性映射 + `1-exp(-rate*dt)` 缓动
  （开快收慢）；脉冲量拉满后指数衰减 + 节流。

## 四、测试与工程

- **无头全链路测试是主武器**（详见 `references/harness.md`）：
  DOM-stub + 主脚本 + driver 拼接跑 Node。抓"严格模式未声明变量""TDZ"这类
  **浏览器里才炸、语法检查抓不到**的致命崩溃。
- **新特性必须补断言，否则改了等于没验。** 每次加交互维度，driver 里逐条加：
  触发条件的构造 → 泵帧 → 断言目标状态。测试从 22 项涨到 32 项就是这么来的。
- **断言别抓衰减残值**：脉冲量（flash 等）触发后指数衰减，晚几帧断言会读到残值并误报。
  在循环里逐帧检查、命中即置 flag。
- **并行编辑同一文件 = 竞态**：同一条消息里对同一 HTML 的多条 Edit 会各读旧版写回、后写覆盖前写。
  实测丢过 8 处修改。👉 处方：**同一文件串行编辑**；批量改动后逐项 grep 验证（找旧值残留/新值缺失）。
- **严格模式教训**：主脚本 `"use strict"` 下，任何赋值给未声明变量（`X = ...` 忘 let）直接
  ReferenceError；顶层一崩、事件绑定全不执行 → 页面"打开完全没反应"。
  拼接测试文件时必须把 `"use strict"` 提升到**整个文件第一行**（否则严格模式失效、恰好掩盖这类 bug）。

## 五、交付与部署

- **发布目录卫生**：部署工具按目录**整包上传**——"把测试脚手架塞进子目录"**不等于**排除。
  发布目录只放：入口 HTML + 运行必需资源（如本地托管的模型文件）+ 文档；
  脚手架（stub/driver/快照/中间 JSON）一律放 `_tools/`（发布目录之外）。
- **部署有前置授权规则**：用户最新一条消息没提"发布/上线"时，**不得静默覆盖已有线上链接**——
  先给本地预览确认，再问。用户说"上线"才推。
- **上线后必须校验线上内容**：用 **Python（urllib）** 拉回 HTML 做"新代码字符串 present +
  旧代码字符串 absent"逐条比对。
  ⚠️ 别用 shell 干这事：PowerShell 双引号里 `\"` 不转义（字符串比对全 false 假结论）；
  中文经 bash shim 传递变乱码。两条加起来会得到完全错误的"检查结果"。
- **提醒用户 Ctrl+F5**：浏览器/CDN 缓存会让你怀疑人生。
- **本地预览用 `python -m http.server <port> --directory <发布目录>`**：
  迭代时改完即刷新看效果；localhost 也是测试摄像头（getUserMedia 需要安全上下文）的唯一便捷通道。

## 六、Windows / PowerShell 环境坑

- **bash 可能突然瘫痪**（PATH 丢失、命令全灭）→ 立刻切 PowerShell，别恋战。
- **PowerShell 输出通道会吞输出/挂起**（尤其原生命令带常驻进程时）→
  **一律写文件再读文件**（`... | Out-File x.txt` / `*> x.txt` 然后 Read 工具读）。
- **PowerShell 参数编码会毁掉传给原生命令的中文与引号** → 要传复杂 JS/中文：
  写进临时文件让程序自己读，或全部用 ASCII/单引号，或直接用 Python 脚本落地。
- **原生命令非零退出会中断整段 PowerShell 脚本**（`$PSNativeCommandUseErrorActionPreference`）→
  逐条拆开执行、用 `if ($?)` 容错，或加 `-ErrorAction Continue`。
- **agent-browser 类常驻工具的深坑**（本次实测）：留 daemon 拖住输出管道（每段 PowerShell 只能
  发一条它的命令、或改用文件重定向 `*>`）；`cmd /c` 可能被安全策略禁；`eval` 跑在隔离环境里
  读不到页面变量（要注入 `<script>` 到主世界）。
  ⚠️ **反思：为"真浏览器测帧率"在这套工具链上折腾了十几个步骤仍未拿到数据，明显过度**——
  工具链连续两三个坑打不通时，果断止损换方案（或直接向用户说明限制），不要沉默地烧时间。
- **删除文件后要用 Glob 复核**（确认真的删了、没误删）；移动/整理用脚本 + 输出清单核对。

## 七、协作与节奏（反思）

- **用户催促（"咋这么慢"）= 最强信号：立刻止损。** 当时在浏览器测量坑里绕远了，
  正确做法是当天早上就该放弃工具链探索，先交付能交付的。
- **模糊需求背后往往是真 bug**：用户说"记得优化一下 UI"，实际抓到三处硬伤
  （按钮并排错位、每帧堆定时器、HUD 与画布元素重叠）。👉 处方：把每次"优化一下 xx"当成
  一次**专项审查**过一遍，而不是换个样式了事。
- **用户反馈的"症状"要翻译成"机制"**："电脑不卡了但是手机卡了" → 移动端档位表没跟上；
  "光污染" → 辉光贴图白色核心；"粒子再小一点、可以不连贯" → 尺寸公式整体乘系数。
- **审美类判断大胆放权、主动收敛选项**：用户授权"怎么好看你怎么来"时，自主决策、
  给出 2~3 个方向的取舍说明，别把决策成本推回给用户。
- **文档与代码同步**：每轮大改后同步更新设计文档与提示词文档（本次维护了《设计思路》《AI生成提示词》两份），
  否则文档会迅速变成"说谎的历史文件"。
