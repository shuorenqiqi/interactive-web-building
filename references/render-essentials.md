# 渲染层速查（canvas-particle-fx 精简版）

> 本文件是 `canvas-particle-fx` 技能的精简副本，供**未安装该技能**的环境兜底。
> 若已安装完整版，以完整版为准。完整版还包含：粒子沿骨架排布、"粒子花"双层结构、常见坑全清单。

## 渲染管线（按此实现，缺一不可）

1. **拖尾清屏**：不要每帧 `clearRect`。每帧把已有内容的 alpha"乘掉"，旧帧渐隐，运动粒子自动拖出 ~300ms 流光。
   - 首选 `destination-out` + 纯色 `fillRect`（`globalAlpha = 1 - 0.8^dt`，夹取 0.12~0.9）。它只乘 alpha，**不采样贴图**。
   - 纯黑底与静态冷晕交给 CSS `position: fixed` 层——静态内容不该参与逐帧重绘。
   - 拖尾让累积发光变亮（稳态约 ×5），所有大面积低透明光晕的 alpha 要折算减半。
2. **辉光用预渲染径向渐变贴图**：64×64 canvas，`drawImage` 缩放绘制。
   - **中心禁止纯白**：色相向白只靠 ~22%，中心 alpha ≤0.9、中层（0.22R）≤0.6、外圈 ≤0.15。这是"光污染"总开关。
   - **绝对禁止 `shadowBlur`**：CPU 软件模糊，几十对象 × 几十线段 = 每帧数千次模糊。发光靠贴图 + `lighter`。
3. **`globalCompositeOperation = "lighter"`** 加色合成；每帧结束恢复 `source-over` 再画 UI 层。
4. **层级**：背景 → 大光斑纵深 → 点云 → 主体 → 星尘 → 特效 → UI。

## 性能诊断顺序（别凭直觉猜）

1. **先量再改**：纯 JS 粒子循环通常可忽略（12000 个对象的取值+判活实测 0.026ms/帧）。别照着"看起来很浪费"的直觉动手。
2. **真瓶颈是填充率**：数每帧有几次**全屏操作**（拖尾、点云拉伸、全屏闪光）。杠杆按收益排序：
   - 减少全屏操作**次数**（静态背景搬去 CSS）；
   - 全屏操作优先纯色 `fillRect`，别用贴图 `drawImage`；
   - **降 DPR**：填充率按分辨率平方涨，`1.5 → 1.25` 省约 30% 像素，柔边发光肉眼看不出差别。
3. 其次是**绘制调用数**（几千次精灵 `drawImage` ≈ 1~2ms）与**状态栈操作**（爆发特效成百上千时，用三角函数直算端点替掉 `save/rotate/restore`；注意 `lineCap` 不再被隔离，需每帧复位）。

## 性能预算（保 60fps 的硬规则）

- 万级点云用 `Uint32Array` 直写 `ImageData`，但用**低分辨率缓冲**（0.3~0.5× 屏幕，拉伸回全屏，朦胧感反而更好），每帧只 `fill(0)` 低分辨率缓冲。
- 高亮粒子在像素缓冲里画十字微芒（上下左右各 1px）；高速粒子沿速度方向拉 2~4px 线。
- 细节系数 LOD：`n * det`，与帧率档位联动（det 1→0.42）。
- **快降慢升**：轻微掉帧（<40fps）立刻降一档；重度掉帧（<27fps）一次降两档并砍推理频率；冷却 0.8~1.2s。升档要连续 3 窗 >56fps + 3s 冷却。
- 手势推理用 GPU delegate；模型文件本地托管；`detectForVideo` 时间戳严格递增。
- "鼠标流畅但手势卡" = 摄像头推理抢主线程，优化方向是降推理频率/分辨率，不是砍渲染。

## 配色与"光污染"处方

黑底 + 加法混合下，"刺眼"只有两个来源：**白色**与**大面积光斑**。按序处理：

1. **去白**：任何 ≥(230,240,255) 都算白——辉光中心、调色板、描边色（含冲击环/闪光/连线 `strokeStyle`）。统一换浅蓝/天蓝；最亮档也保留蓝调，如 `(206,234,255)`。层次用"同色相深浅"表达，不是"颜色→白"。
2. **柔化贴图**：中层 0.85→0.6、外圈 0.25→0.15、中心 1→0.9。
3. **粒子做小**：用户要"不连贯/粒子感"时，**缩尺寸比减数量有效**——尺寸公式整体 ×0.6（`4.5+sz*7 → 2.8+sz*4.0`），alpha 微升（0.62→0.7）保持单点可读。总光通量仍大降（面积按平方缩）。
4. **压能量增益**：`gBright = 1 + en*a + flash*b` 里的 `b` 也要压（0.8→0.6），否则爆发瞬间依旧过曝。
5. **量化验证离散度**（看不到图时）：从几何快照算"最近邻距离 / 渲染尺寸"，NN 中位/sz 中位在 0.5~1 且 `NN > 0.5*sz` 占比 >60% ≈ 清晰点阵；<0.5 说明还在糊。先排除花心区域。

## 交互映射

- **位置**：欠阻尼弹簧 `v += (t-x)*k*dt - v*c*dt`（k≈40，c≈0.11k → ζ≈0.35，带滞后回弹的重量感）。直接赋值没有生命感。
- **连续量**：线性映射 + `1-exp(-rate*dt)` 缓动（开快收慢）。
- **脉冲**：能量拉满后 `energy *= 0.1^dt` 指数衰减，作用于流速/尺寸/亮度；节流 ≥400ms。
- **待机**：无输入回中 + 缓慢呼吸（`0.5+0.17*sin(t*0.4)`）；控制冷却计时器 `ctlT` 每帧衰减，输入时重置 ~0.2s。
- 手势判定用归一化比值（÷掌宽）；先判握拳再判捏合避免歧义。

## 界面收尾三查（DOM 测试抓不到）

1. **按钮会并排**：`inline-block` 按钮只靠 `margin-top` 分不了行，一律用 `flex-direction: column` + `gap`。
2. **延迟换内容必须用目标值判重**：`if (el.textContent !== t) setTimeout(...)` 会在 240ms 空窗期每帧排一个新定时器（60fps ≈ 14 个）。用独立变量 `cur` 判重 + `clearTimeout`；**淡出时长必须 ≤ 换字延迟**。
3. **HUD 与 canvas 绘制物对坐标**：canvas 内常驻元素与 CSS 定位的 HUD 是两套坐标系，极易重叠。加常驻信息前实算一遍 `x/y/w/h` 与 `right/bottom`；canvas 内缩略图宽度跟屏宽缩放（`Math.min(176, W*0.32)`）。
4. 触摸/鼠标提示分路：`matchMedia("(hover: none)")`，别让手机看到"左键/右键"。
